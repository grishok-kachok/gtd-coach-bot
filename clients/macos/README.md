# Половина коуча, которая живёт на ноутбуке

Бот на сервере — не весь коуч. Вторая половина работает на макбуке владельца и
делает две вещи, без которых память разъезжается:

| Скрипт | Что делает | Кто запускает |
|---|---|---|
| `coach-dialog-sync.py` | вынимает из транскриптов Claude Code реплики человека и текстовые ответы коуча и шлёт их в архив бота по ssh (`docker exec -i coach-bot python -m src.import_laptop`) | launchd, раз в 2 минуты |
| `coach-brain-sync.sh` | держит папку памяти в согласии с GitHub: своё отдаёт, чужое (правки бота) забирает | launchd: при изменении файлов + раз в 2 минуты |
| `coach-context-inject.py` | SessionStart-хук Claude Code: кладёт выжимки памяти в контекст новой сессии **кодом**, а не надеждой, что агент вспомнит прочитать файл | сам Claude Code |

Файлы в `launchd/` — задания для macOS.

## Зачем они здесь, а не только на ноутбуке

Это ровно тот класс потерь, который больнее всего: скрипт существует в одном
экземпляре на диске, работает годами, и его никто не хватится, пока диск жив.
Репозиторий — вторая копия и заодно история правок.

**Источник правды — этот репозиторий.** В `~/.claude/scripts/` лежат symlink-и
сюда, поэтому правка файла здесь сразу становится боевой, а `git status`
показывает всё, что менялось.

## Установка на чистой машине

```bash
# 1. скрипты — ссылками, чтобы не было двух расходящихся копий
mkdir -p ~/.claude/scripts
for f in coach-brain-sync.sh coach-context-inject.py coach-dialog-sync.py; do
    ln -sf "$PWD/clients/macos/$f" ~/.claude/scripts/$f
done

# 2. фоновые задания
cp clients/macos/launchd/*.plist ~/Library/LaunchAgents/
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.vefmv.coach-brain-sync.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.vefmv.coach-dialog-sync.plist

# 3. хук памяти — в .claude/settings.json проекта, вторым SessionStart-хуком
```

Пути внутри скриптов и plist-ов пока прибиты гвоздями под владельца
(`/Users/vasiliy/...`, ssh-алиас `bronto`) — при переезде на другую машину или
раздаче ученикам их надо вынести в настройки.

## Грабли

- **launchd запускает системный `/usr/bin/python3`** (на macOS это 3.9), а не свежий
  из PATH. Поэтому в скриптах стоит `from __future__ import annotations` — без него
  падает разбор `dict | None`, причём молча, в `.err`-файл.
- **Смещения по файлам двигаются только после успешной доставки.** Отвалился ssh —
  ничего не потеряно, следующий прогон дошлёт. Обратная сторона: если импорт падает
  на одной строке, канал встаёт весь — поэтому кривая строка на сервере считается
  «битой записью», а не аварией.
- **Служебные тексты Claude Code** (`<command-name>`, `<system-reminder>`,
  `<task-notification>`, «Caveat:») приходят в транскрипте как реплики человека.
  Их обязательно отбрасывать: они и мусорят ночную выжимку, и выглядят как
  «человек отозвался» — то есть отменяли бы дожим.
