# gtd-coach-bot — телеграм-коуч

Коуч по личной эффективности, который живёт в телеграме и **помнит** человека:
накапливает понимание, а не начинает каждый раз с чистого листа. Голос —
основной вход: наговорил → расшифровалось → коуч понял, разложил дела
по Todoist и записал значимое в память.

**Дверь к коучу одна — телеграм.** Компьютер нужен только как верстак: поставить,
обновить, заглянуть в память глазами. Разговаривать с коучем оттуда нельзя —
у него один непрерывный разговор с закладкой, и второй собеседник ломает память.

Как это ставить целиком и с чего начинать — [README плагина
`gtd-coach`](https://github.com/vefmvai/gtd-coach). Здесь — про сам бот.

## Из чего состоит

| Файл | За что отвечает |
|---|---|
| `src/main.py` | Телеграм: поллинг, голос, чек-ины, ночной прогон |
| `src/engine.py` | **Движок**: Claude Agent SDK, непрерывная сессия, инструменты |
| `src/modes.py` | Режимы контекста: что коуч берёт с собой в разговор |
| `src/sessions.py` | Закладка разговора — какой `session_id` продолжать |
| `src/todoist.py` | Инструменты Todoist — обёртки над ядром `todoist_mcp` |
| `src/gcal.py` | Инструменты Календаря — обёртки над ядром `gcal_mcp` |
| `src/voice.py` | Расшифровка голосовых: Groq, при осечке — OpenAI |
| `src/retry.py` | Повтор сетевых операций: сеть моргнула — не потеряли голосовое |
| `src/brain.py` | Синхронизация памяти через git |
| `src/digest.py` | Ночная выжимка: день из сырья, неделя и месяц — из дней |
| `src/detectors.py` | Ночной обход завалов: шесть приборов с нормами |
| `src/comments.py` | Вторая дверь: обращения к коучу в комментариях Todoist |
| `src/tidy_history.py` | Ночная причёска истории: день → один осмысленный коммит |

**Роли коуча в этом репозитории нет.** Конституция, правила памяти, методология
и навыки живут в отдельном плагине
[`gtd-coach`](https://github.com/vefmvai/gtd-coach) и приезжают сюда
смонтированным клоном (`/plugin`, только на чтение). Один дом у того, как коуч
работает, — и бот в него не пишет, а только читает.

Инструменты — тоже отдельные репозитории:
[`todoist-mcp`](https://github.com/vefmvai/todoist-mcp) и
[`gcal-mcp`](https://github.com/vefmvai/gcal-mcp). Одно объявление кнопки
на сервис, обе стороны строятся из него.

## Путь голосового

Три шага: забрать ссылку на файл у Telegram → скачать аудио → расшифровать.
Сеть иногда моргает (однажды голосовое потерялось на первом шаге —
`ReadTimeout` в `get_file`), поэтому каждый шаг повторяется до 10 раз
с нарастающей паузой (`src/retry.py`). Повторяются только сбои, которые чинятся
сами: таймауты, обрывы, 429, 5xx. Отказ по существу (битый `file_id`, неверный
ключ) вылетает сразу — крутить его бессмысленно.

Расшифровка вдобавок держит два сервиса: **Groq** (бесплатный тир) и на любой
его осечке сразу **OpenAI** — одна попытка основному, остальные девять
запасному. Человек видит происходящее: с третьего повтора бот пишет «связь
шалит», при переходе на запасной — «Groq не отвечает, расшифровываю через
OpenAI». Если не вышло совсем — сообщение с числом попыток и причиной.

## Память: три слоя

1. **Разговор** — сессия SDK, файл на диске. Переживает паузы и рестарты.
2. **Выжимки** — каждую ночь в 03:00 день перечитывается и складывается в
   `память/журнал/выжимки/дни/`, после чего разговор начинается с чистого листа.
   Воскресной ночью собирается неделя, первого числа — прошлый месяц. И неделя,
   и месяц собираются **из дневных выжимок в базе**, а не из уровня выше и не
   из сырья: месяц из недель был бы пересказом пересказа, а месяц сырья — около
   492 000 токенов, он просто не влезет.

   В начало нового разговора подставляется **ровно столько кусков, сколько
   назначил режим** (`режимы.md` в плагине; рабочий день — 3 месяца, 5 недель,
   7 дней). Постоянное количество делает размер памяти умножением, известным
   заранее, — резать по живому не нужно никогда. Журнал в мозге держится в том же
   окне: файлы старше него удаляются, тексты остаются в базе и в истории git.
3. **Мозг** — папка `память/` из **своего приватного репозитория** памяти.
   Единственный экземпляр живёт на сервере рядом с ботом.

## Причёска истории (тоже ночью)

Машинные коммиты («досохранение») делает серверный сторож по расписанию — он
звать модель не может. Ночью, сразу после выжимки, `tidy_history.py` сворачивает
день в один коммит и подписывает его по-человечески, глядя на реальный diff.

История переписывается — значит осторожность важнее красоты:

- только когда рабочее дерево чистое и локальная история совпадает с удалённой;
- `--force-with-lease`, чтобы не затереть чужой push;
- после свёртки дерево сверяется с исходным: изменилось хоть на байт — откат.

## Развернуть

```bash
git clone git@github.com:vefmvai/gtd-coach-bot.git /opt/apps/gtd-coach-bot
cd /opt/apps/gtd-coach-bot
cp .env.example .env && vim .env          # токены, см. комментарии в файле
git clone <свой-приватный-репозиторий-памяти> data/brain
docker compose up -d --build
docker compose logs -f
```

Мозг — **свой у каждого**: приватный репозиторий, который вы заводите себе сами.
Пустой скелет с объяснениями «что сюда кладут» лежит в плагине,
`brain-template/`. Наполняет его навык-онбординг разговором, а не вы руками.

Плагин и инструменты приезжают в контейнер смонтированными клонами — адреса
томов в `docker-compose.yml`.

Почему поллинг, а не вебхуки: входящие вебхуки Telegram доступны не везде,
бот сам ходит за обновлениями.

## Проверить

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt pytest
.venv/bin/pytest tests/ -q
```

Ротацию памяти нельзя проверить живым прогоном: одна проверка стоит суток
ожидания, а «месяц в конце месяца» — тридцати. Поэтому год жизни бота
проигрывается на синтетических датах за секунду, без вызова модели. Тесты
стерегут постоянный размер окна, отсутствие дырок в покрытии, ISO-ключ недели,
календарные границы месяца и сборку уровней из базы, а не из файлов.

## Обслуживание

Код правится **только на своём компьютере** и приезжает на сервер через GitHub:
компьютер → `git push` → на сервере `git pull`. Серверный клон — цель выкатки,
а не источник правды: его deploy-ключ read-only, а хук `pre-commit` там отклоняет
коммиты. Так на сервере физически не может завестись версия кода, которой нет
больше нигде.

```bash
docker compose logs -f --tail=100    # что происходит
docker compose restart               # разговор не теряется — session_id на диске
git pull && docker compose up -d --build
```

### Здоровье

`docker ps` показывает у контейнера `healthy` / `unhealthy`. Проверка —
`src/healthcheck.py`: свежесть пульса главного цикла (`/tmp/coach-heartbeat`,
обновляется раз в минуту) плюс живой ответ Telegram. Посмотреть причину:

```bash
docker inspect --format '{{json .State.Health}}' gtd-coach-bot | python3 -m json.tool
```

Команды в чате: `/start` — проверка связи, `/new` — начать разговор с чистого
листа (память при этом остаётся), `/reset` — сбросить состояние обряда.
